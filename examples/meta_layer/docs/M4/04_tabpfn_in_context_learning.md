# M4 Tutorial 4: TabPFN and In-Context Learning

*Part 4 of 4. Previous: [3. Training and evaluation](03_training_and_evaluation.md).*

Part 3 ended with a problem: given only 16 to 256 labelled events of a new regulator, a gradient-boosted model trained from scratch overfits and does worse than predicting zero. This part explains a different kind of model, a **tabular foundation model**, which does not train on those examples at all, and shows exactly how M4 uses one.

---

## 1. The idea in one paragraph

An ordinary model learns its parameters from *your* training set. A tabular foundation model learns its parameters once, in advance, from millions of *synthetic* datasets; then, given your small training set and a query row, it predicts the query's label in a single forward pass, with no gradient steps. The training set is not used to update weights; it is read as **context**, much as a language model reads a few examples in its prompt. This is **in-context learning**. TabPFN is the best-known model of this kind.

## 2. Where it comes from: prior-data fitted networks

Suppose we knew the true family of data-generating processes, each described by parameters $\phi$, with a prior $p(\phi)$. The ideal prediction for a query $x$ given a training set $D = \{(x_1, y_1), \dots, (x_k, y_k)\}$ is the **posterior predictive distribution**

$$
p(y \mid x, D) = \int p(y \mid x, \phi)\, p(\phi \mid D)\, d\phi ,
$$

which averages the predictions of every plausible explanation $\phi$ of the data, weighted by how well each explains $D$. With few examples, this averaging is exactly what prevents overfitting: no single explanation is trusted too much.

The integral is intractable for rich priors. **Prior-data fitted networks** (PFNs; Müller et al., 2022) approximate it by learning. Repeat many times:

1. draw a data-generating process $\phi \sim p(\phi)$;
2. draw a dataset from it, and split it into a context set $D$ and held-out queries;
3. train a transformer $q_\theta(y \mid x, D)$ to predict the held-out labels from the context.

Minimising the prediction loss over this stream trains $q_\theta$ to approximate $p(y \mid x, D)$ for data like the prior's. At use time, a real dataset plays the role of $D$.

## 3. TabPFN

TabPFN (Hollmann et al., ICLR 2023; extended in *Nature*, 2025) is a PFN for tables. Its main ingredients:

- **The prior is a distribution over structural causal models.** Synthetic tables are generated by random causal graphs with random functional relationships, noise, and feature types, so the network learns to handle the variety found in real tabular data: irrelevant features, interactions, nonlinearities, categorical and heavy-tailed columns.
- **Two-way attention over cells.** Each table cell gets its own representation. Layers alternate between attending across the features of a row and across the samples of a column. Query rows attend to the context rows, not to each other, so predictions do not depend on which other queries are in the batch.
- **Distributional regression output.** For regression, TabPFN predicts a distribution over binned target values rather than a single number; the point prediction is its mean (or another summary).
- **Ensembling over input transformations.** Predictions are averaged over several preprocessings of the features and target.

The *Nature* version, **TabPFN v2**, handles up to about 10,000 context rows and 500 features; later releases (2.5, 3, 3.5) extend this but come with a more restrictive license (section 6). M4 uses v2.

## 4. Why it fits the M4 few-shot problem

| Problem in part 3 | How TabPFN addresses it |
|---|---|
| Only 16 to 256 labelled events per new regulator | built for small context sets; its prior supplies what the data cannot |
| XGBoost overfits 229 features from 16 rows | approximate Bayesian averaging instead of fitting a single model |
| No time to tune hyperparameters per regulator | none to tune; one forward pass |
| Features differ wildly in scale (some ratios reach $10^6$) | trained on heavy-tailed synthetic columns; internal transformations |

There is a conceptual fit too. Part 2 identified the missing piece of M4 as a regulator representation $z_R$. In TabPFN, the context set *is* the regulator's representation: the network reads $R$'s $k$ labelled events and conditions every prediction on them. In-context learning infers a task embedding on the fly.

What TabPFN does **not** bring is biology. Its prior is generic tabular data, not splicing. It cannot know that UG-rich sequence matters for TDP-43 unless that is visible in the features and in the context examples.

## 5. How M4 uses it

Two methods in `examples/meta_layer/17_m4_fewshot_benchmark.py`, both on the same 229 compact features as every other method.

**`tabpfn`: the regulator's examples only.**

```python
# Xs, ys: the k shots of held-out regulator R (events in training genes)
# Xt:     R's events in test genes
model = TabPFNRegressor(device=device, random_state=draw)
model.fit(Xs, ys)          # stores the context; no gradient steps
y_hat = model.predict(Xt)  # one forward pass, queries attend to the k shots
```

**`pooled_tabpfn`: a prior plus an in-context correction.** The pooled XGBoost model (trained on all other regulators) provides a regulator-agnostic prior; TabPFN learns, from the $k$ shots, how $R$ deviates from it:

$$
\hat y = \underbrace{f_{\text{pooled}}(x)}_{\text{prior from other regulators}} + \underbrace{q_\theta\big(x \mid \{(x_j,\ y_j - f_{\text{pooled}}(x_j))\}_{j=1}^{k}\big)}_{\text{TabPFN on the residuals}} .
$$

This is the tabular analogue of meta-learning: a shared model for what all regulators have in common, and fast adaptation for what is specific to one.

**Operational details.**

| Aspect | Setting |
|---|---|
| Device | CUDA on a GPU pod; CPU on a laptop (the Apple-silicon backend needs torch ≥ 2.6; the project pins 2.5.1) |
| Context size | $k \in \{16, 64, 256\}$, far below TabPFN's limits |
| Draws | 3 random shot sets per $k$, averaged within each regulator |
| Weights | unweighted (TabPFN takes no sample weights here) |
| Model version | TabPFN v2 by default (`--tabpfn-version` to change) |
| Cost and parallelism | one call (8 ensemble members, 229 features, ~2,000 query rows) takes 7–10 s, nearly all single-threaded CPU preprocessing; a full benchmark is ~5,000 calls, so `--tabpfn-workers` runs them on a bounded process pool (8 workers on a 96-core pod). Parallel and serial runs give identical metrics. |
| Preflight | `_tabpfn_ready()` runs a tiny fit first; if it fails (for example, no network to download weights), the TabPFN methods are skipped with the reason printed and the rest of the benchmark runs |

## 6. Licensing: why M4 uses TabPFN v2

The installed package (`tabpfn` 9.2.0) defaults to 3.5, so M4 selects v2 explicitly. For M4's context sizes ($k \le 256$ rows, 229 features), v2 is well within its design range.

## 7. Results

TabPFN v2 ran on the full benchmark on 2026-10-19 (S3, 185 held-out regulators, three shot draws per $k$):

| Method | $k$ = 16 | $k$ = 64 | $k$ = 256 |
|---|---:|---:|---:|
| `xgb` (direction acc.) | 0.516 | 0.525 | 0.529 |
| `tabpfn` (direction acc.) | 0.515 | 0.534 | **0.565** |
| `pooled_tabpfn` (direction acc.) | 0.518 | 0.526 | 0.545 |

The three questions:

1. **Does `tabpfn` beat `xgb`?** Yes from $k = 64$, and for 122 of 185 regulators at $k = 256$. The small-data argument holds: with a strong prior, a few hundred examples are usable; without one, they are overfit. TabPFN's error also approaches that of predicting zero (weighted MAE 0.095 vs 0.093), while XGBoost's stays worse (0.108).
2. **Does `pooled_tabpfn` beat `pooled`?** Yes (0.545 vs 0.520 at $k = 256$), but it is worse than `tabpfn` alone: the pooled prior carries little S3 signal, so correcting it is a weaker start than learning from the shots directly.
3. **Which regulators does it learn?** The best are 3′ splice-site and core spliceosome factors (U2AF1 0.811, U2AF2 0.756, SF3A3 0.752, RBM25 0.764), QKI (0.813, a strong motif), and MAGOH (0.762, exon-junction complex): regulators with strong, consistent programs.

## Summary

- A tabular foundation model is pretrained on synthetic datasets to approximate Bayesian prediction; given a small table it predicts in one forward pass, with no training.
- In M4, TabPFN reads $k$ examples of a held-out regulator as context: alone (`tabpfn`) or as a correction to a model of all other regulators (`pooled_tabpfn`).
- The context set acts as an implicit regulator representation, which is the piece the current M4 models otherwise lack.

**References.** Müller et al., *Transformers Can Do Bayesian Inference*, ICLR 2022. Hollmann et al., *TabPFN: A Transformer That Solves Small Tabular Classification Problems in a Second*, ICLR 2023. Hollmann et al., *Accurate predictions on small data with a tabular foundation model*, *Nature* 2025.
